# Layouts and topic prompts

Choose structure by teaching purpose. The reference supplies materials and lighting; it does not impose circular composition.

| Concept | Possible layout | Elements |
|---|---|---|
| API request and response | Paired cards with directional connectors | Client, endpoint, payload, response |
| HTTP methods | Comparison table | Method, intent, example, relevant property |
| Protocol stages | Sequential pipeline | Ordered stage cards and connectors |
| Headers or configuration | Key/value or property table | Editable names and values over generated panels |
| Architecture | Layered blocks or branching diagram | Services, storage, queues, boundaries |
| Before and after | Two-column comparison | Matched objects with focused differences |
| Tradeoffs | Matrix or comparison cards | Options and editable criteria |
| Ecosystem overview | Grid, grouped cards, or optional orbit | Related capabilities or tools |

Use purple for Python/AI/general engineering, blue for APIs/cloud/backend, green for health/success, amber for warnings/frontend/builds, and red for security/incidents. These are subject suggestions; choose the user's preferred accent when specified.

## API exchange example

> Topic: HTTP request and response. Create two distinct glossy charcoal beveled cards representing a client and a server, connected left-to-right for a request and right-to-left for a response. Use a black background, blue accent edges, restrained bloom, and soft rim lighting. Leave clear space above each card and beside each connector for editable labels. Keep the composition front-facing and readable in landscape video. No incidental text or watermark.

Overlay the accurate labels in Remotion. Step-fade the request and response overlays at their narration phrases. To reveal the cards independently, request separate assets; otherwise fade the generated plate together.

## Table example

> Topic: comparing HTTP methods. Create a wide, front-facing glossy charcoal comparison-table backing plate on black, with a header band and four clearly separated horizontal row panels. Use subtle blue beveled edges and local neon bloom. Leave cells empty for exact editable text. Keep generous spacing and clear margins for subtitles. No lettering or watermark.

Use actual required rows and columns, not an arbitrary fixed count. Populate and verify exact content in Remotion; reveal row overlays as the narration introduces each method. Alternative structures include key/value tables, matrices, and paired comparisons.

## Pipeline example

> Topic: a request passing through middleware. Create a horizontal series of distinct glossy charcoal processing blocks with directional connectors, on black, with blue accents and soft rim lighting. Show a clear entry and exit, and reserve negative space for editable stage labels. Use rounded bevels and restrained bloom. No incidental lettering or watermark.

Use blur-in for the plate, phrase-timed step fades for accurate overlays, and blur-out after the final explanation. Generate separate block layers if staged object entrances are needed.

## Explicit orbital reference match

When the user requests the reference composition, a central Python logo on a glowing circular podium with surrounding glossy capability icons and a dashed elliptical orbit is appropriate. Select only meaningful icons. The layout, icon count, and badges are not requirements for other scenes. Apply the same phrase-timed fade/blur rules rather than an automatic rotating loop.
